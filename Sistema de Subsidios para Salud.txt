En las entidades del Estado peruano (como la Red de Salud Huánuco, bajo regímenes D.L. 276, D.L. 1057 CAS o D.L. 728), el control de asistencias y licencias médicas se rige por disposiciones laborales y de seguridad social estrictas:
* Ley N° 26790 y D.S. N° 009-97-SA (Ley de Modernización de la Seguridad Social en Salud):
   * Durante los primeros 20 días acumulados de descanso médico dentro del año calendario (del 1 de enero al 31 de diciembre), la entidad empleadora (Red de Salud) asume el pago de la remuneración íntegra de manera directa.
   * A partir del día 21 acumulado, nace el derecho al Subsidio por Incapacidad Temporal para el Trabajo financiado por EsSalud. La entidad sigue abonando la remuneración al trabajador mediante la figura de pago diferido/subsidio y posteriormente gestiona el trámite de reembolso/recupero ante EsSalud.
* Directivas de EsSalud para Canje de CITT:
   * Si el servidor presenta certificados médicos emitidos por clínicas o médicos particulares (CMP), cuando el descanso supera el vigésimo día acumulado, esos descansos deben canjearse obligatoriamente por el CITT (Certificado de Incapacidad Temporal para el Trabajo) expedido por EsSalud. Sin CITT, EsSalud no aprueba el reembolso del subsidio.

3. Lógica del Motor de Subsidios (El Núcleo del Sistema)
El cálculo normativo debe ejecutarse en el backend (o en una función SQL) cada vez que se procesa el consolidado anual de un trabajador.
// services/subsidioService.ts

export interface BalanceSubsidio {
 diasTotalesAnio: number;
 diasEmpleador: number;      // Días 1 al 20 asumidos por la Red
 diasSubsidiados: number;    // Día 21 en adelante (reembolso EsSalud)
 aplicaSubsidio: boolean;
 licenciasCronologicas: any[];
}

export function calcularSubsidioAnual(licencias: any[]): BalanceSubsidio {
 // 1. Filtrar solo licencias de tipo Enfermedad Común o Accidente
 const licenciasSalud = licencias
   .filter(l => l.tipoLicencia === 'ENFERMEDAD_COMUN' || l.tipoLicencia === 'ACCIDENTE_COMUN')
   .sort((a, b) => new Date(a.fechaInicio).getTime() - new Date(b.fechaInicio).getTime());

 let acumuladorDias = 0;
 let diasEmpleador = 0;
 let diasSubsidiados = 0;

 for (const lic of licenciasSalud) {
   const diasActuales = lic.diasOtorgados;

   if (acumuladorDias + diasActuales <= 20) {
     // Todo el bloque cae dentro de los primeros 20 días
     diasEmpleador += diasActuales;
   } else if (acumuladorDias < 20 && acumuladorDias + diasActuales > 20) {
     // Bloque mixto: parte la cubre la Red y parte pasa a EsSalud
     const restanteEmpleador = 20 - acumuladorDias;
     diasEmpleador += restanteEmpleador;
     diasSubsidiados += (diasActuales - restanteEmpleador);
   } else {
     // A partir del día 21 acumulado, todo es subsidio
     diasSubsidiados += diasActuales;
   }

   acumuladorDias += diasActuales;
 }

 return {
   diasTotalesAnio: acumuladorDias,
   diasEmpleador,
   diasSubsidiados,
   aplicaSubsidio: acumuladorDias > 20,
   licenciasCronologicas: licenciasSalud
 };
}

// lib/pdfGenerator.ts
import puppeteer from 'puppeteer';
import { PDFDocument } from 'pdf-lib';
import fs from 'fs/promises';

export async function compilarExpedienteCompleto(datosInforme: any, rutasEvidencias: string[]): Promise<Buffer> {
 // 1. Renderizar la carátula y el informe técnico con Puppeteer
 const browser = await puppeteer.launch({ headless: true, args: ['--no-sandbox'] });
 const page = await browser.newPage();

 const htmlContent = generarHtmlPlantilla(datosInforme);
 await page.setContent(htmlContent, { waitUntil: 'networkidle0' });
 const pdfPrincipalBytes = await page.pdf({ format: 'A4', printBackground: true });
 await browser.close();

 // 2. Fusionar con las evidencias escaneadas (CITTs a partir del día 21) usando pdf-lib
 const pdfFinal = await PDFDocument.load(pdfPrincipalBytes);

 for (const ruta of rutasEvidencias) {
   try {
     const archivoBuffer = await fs.readFile(ruta);
     const pdfAnexo = await PDFDocument.load(archivoBuffer);
     const paginasCopiadas = await pdfFinal.copyPages(pdfAnexo, pdfAnexo.getPageIndices());
     paginasCopiadas.forEach(pagina => pdfFinal.addPage(pagina));
   } catch (error) {
     console.error(`No se pudo anexar el archivo: ${ruta}`, error);

Cómo procesar miles de registros de Excel sin colapsar el sistema
El error común al importar archivos pesados es procesar fila por fila en un bucle (for ... await insert()), lo que satura la memoria y provoca caídas por tiempo de espera (timeout). Para una red de salud con 13 microredes, la estrategia técnica debe ser:
   * Lectura por Streams (Transmisión en bloques): En lugar de cargar todo el archivo .xlsx de golpe en la memoria RAM del servidor, se utiliza el lector por flujo de exceljs o xlsx-stream-reader. El sistema procesa lotes de 1,000 filas a la vez.
   * Inserciones en Lote (Bulk Insert): Se utiliza prisma.licencia.createMany() o sentencias SQL nativas (UNNEST / COPY FROM). Guardar 5,000 filas de golpe toma menos de 1.5 segundos en PostgreSQL; hacerlo una por una tomaría varios minutos.
   * Transacciones Atómicas ($transaction): Si la fila 3,200 tiene un DNI corrupto o una fecha inválida, la transacción revierte todo el lote para evitar que queden datos a medias en el sistema.
   * Indexación en PostgreSQL: Se configuran índices compuestos en las columnas de búsqueda frecuente:
CREATE INDEX idx_licencias_trabajador_anio ON "Licencia" ("trabajadorId", "anioEjercicio");
CREATE INDEX idx_trabajadores_microred ON "Trabajador" ("microredId", "establecimientoId");

Esto garantiza que el cálculo de los 20 días para miles de personas se ejecute en milisegundos.
Vite vs Next.js: ¿Cuál es la mejor opción para este proyecto?
La decisión depende de cómo estructurarás la arquitectura del servidor. En un sistema estatal que luego irá a un VPS privado con Docker y Nginx, hay diferencias operativas decisivas:


Criterio
	Next.js (App Router)
	Vite (React SPA) + Backend Aparte (Express/Fastify)
	Arquitectura
	Monolito Fullstack: Frontend y APIs viven en el mismo proyecto.
	Separada: Dos proyectos independientes (uno web y una API Node.js).
	Generación de PDFs (Puppeteer)
	Directa en las rutas de servidor (/api/reportes/pdf).
	Obliga a crear un backend Express dedicado para correr Chromium.
	Despliegue en VPS (Docker)
	1 solo contenedor para todo el sistema (más simple de mantener).
	2 contenedores (uno Nginx para Vite y otro Node para la API) + configuración CORS.
	Seguridad de Archivos
	Las rutas protegidas verifican sesión antes de servir el PDF/evidencia.
	Requiere configurar middleware de tokens en un backend externo.
	Rendimiento UI
	Excelente (usa React Server Components y Client Components).
	Extremadamente rápido en desarrollo local.
	El veredicto definitivo: Next.js (App Router + TypeScript)
Para la Red de Salud Huánuco, Next.js es la mejor opción por tres razones prácticas:
      1. Un solo proyecto y un solo despliegue: No necesitas configurar dos repositorios, dos puertos ni lidiar con problemas de CORS entre el frontend y el backend. Al desplegar en el VPS privado, corres un único contenedor Docker detrás de Nginx.
      2. Puppeteer y lectura de Excel integrados: Las tareas pesadas (parsear el archivo Excel y ensamblar los PDFs con los sellos y anexos de EsSalud) se ejecutan en las rutas internas de Next.js (Server Actions o Route Handlers), compartiendo exactamente los mismos tipos de TypeScript y esquemas de base de datos que la interfaz visual.
      3. Escalabilidad de roles: La protección de rutas para los 3 perfiles (Super Admin, Admin Microred y Consulta pública) se resuelve directamente en el middleware.ts del servidor, impidiendo accesos no autorizados antes de que la página termine de cargar.

3. Motor Aislado de Reglas de Negocio (lib/domain/calculoSubsidio.ts)
Esta función procesa la regla de los 20 días de forma desacoplada de la interfaz. Si la normativa de EsSalud cambia, solo modificas este archivo.
Crea el archivo lib/domain/calculoSubsidio.ts:
import { RegistroLicenciaTabla } from '@/types/licencia';

export const DIAS_MAXIMOS_EMPLEADOR = 20;

export interface ResultadoSubsidio {
 diasEmpleador: number;
 diasSubsidiados: number;
 requiereSubsidio: boolean;
}

export function evaluarReglaSubsidio(totalDias: number): ResultadoSubsidio {
 if (totalDias <= DIAS_MAXIMOS_EMPLEADOR) {
   return {
     diasEmpleador: totalDias,
     diasSubsidiados: 0,
     requiereSubsidio: false,
   };
 }

 return {
   diasEmpleador: DIAS_MAXIMOS_EMPLEADOR,
   diasSubsidiados: totalDias - DIAS_MAXIMOS_EMPLEADOR,
   requiereSubsidio: true,
 };
}

	Restricción Inquebrantable
	src/app

	Conexión a base de datos y utilidades de seguridad transversales.

	Agrupa todo lo que un módulo necesita para funcionar (UI + Servidor).

Para entender cómo se comunican las capas sin generar código espagueti, este será el flujo exacto cuando un administrador cargue un Excel:
      1. Interacción (Shared/UI): El usuario arrastra el Excel en un componente dentro de shared/components/ui/Dropzone.tsx.
      2. Orquestación (Features/UI): El componente ContenedorLicencias.tsx recibe el archivo y llama a un Server Action.
      3. Procesamiento (Features/Actions): El archivo features/licencias/actions.ts recibe el documento, valida los permisos del usuario y lo envía al servicio.
      4. Dominio (Features/Services): lectorExcel.ts procesa 5,000 filas en memoria. Llama a calculoSubsidio.ts para determinar quiénes pasaron los 20 días.
      5. Persistencia (Core/DB): Se ejecuta una transacción masiva mediante prisma.ts insertando los registros de golpe.
      6. Respuesta (App): La ruta actualiza la tabla automáticamente mediante la revalidación de caché de Next.js (revalidatePath).
